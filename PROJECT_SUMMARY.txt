================================================================================
  OVERVIEW
================================================================================

SecureApp is a production-grade Spring Boot backend with enterprise security:
  - Session-based authentication with JDBC-backed sessions (PostgreSQL)
  - DPoP (Demonstration of Proof-of-Possession) — RFC 9449
  - CSRF protection (CookieCsrfTokenRepository)
  - Role-based access control (AuthorizationInterceptor + RolePermissionMapping)
  - Comprehensive security headers (CSP, HSTS, X-Frame-Options, etc.)
  - BCrypt password hashing (strength 12)

================================================================================
  REQUEST FLOW
================================================================================

  Client → DPoPAuthenticationFilter → SessionValidationFilter
         → SecurityHeadersFilter → CSRF Filter
         → AuthorizationInterceptor → Controller

  Public endpoints (no auth): /auth/login, /auth/register, /auth/logout, /health
  Protected endpoints: All others require session + DPoP proof + role check

================================================================================
  API ENDPOINTS (Base URL: http://localhost:8080/api)
================================================================================

  PUBLIC:
    POST  /auth/register     Create new user (ROLE_USER by default)
    POST  /auth/login        Login + DPoP key binding (requires DPoP header)
    POST  /auth/logout       Invalidate session
    GET   /health            Health check

  PROTECTED (requires JSESSIONID cookie + DPoP header):
    GET   /auth/me           Get current user profile
    GET   /dashboard         Dashboard (ROLE_USER, ROLE_ADMIN)
    GET   /admin/users       Admin-only user list (ROLE_ADMIN)

================================================================================
  DPoP (Demonstration of Proof-of-Possession)
================================================================================

  1. Client generates ECDSA P-256 keypair locally (WebCrypto API)
  2. At login: client sends self-signed DPoP proof JWT with public key
  3. Server validates proof and binds public key to the session
  4. All subsequent requests must include a fresh DPoP proof
  5. Server compares JWK thumbprint with session-bound thumbprint
  6. Replay protection via Caffeine cache (jti uniqueness check)

  DPoP Header format: DPoP: <signed-jwt>
  JWT type: dpop+jwt
  Algorithm: ES256 (ECDSA P-256)
  Claims: htm (method), htu (URI), iat (timestamp), jti (unique ID)

================================================================================
  PROJECT STRUCTURE
================================================================================

  config/
    SecurityConfig.java          Filter chain, CORS, CSRF, session management
    SessionConfig.java           @EnableJdbcHttpSession (15-min timeout)
    WebMvcConfig.java            Registers AuthorizationInterceptor

  controller/
    AuthController.java          Login (with DPoP), register, logout, /auth/me
    DashboardController.java     /health, /dashboard, /admin/users

  dpop/
    DPoPAuthenticationFilter.java    Validates DPoP proof on every request
    DPoPConstants.java               Constants (headers, claims, cache config)
    DPoPProofValidator.java          RFC 9449 proof validation logic
    DPoPReplayProtectionService.java Caffeine cache for jti replay protection
    DPoPSessionBindingService.java   Binds public key to session at login
    DPoPValidationException.java     Custom exception for validation failures

  dto/
    ApiResponse.java             Standard response wrapper
    LoginRequest.java            {username, password}
    SignUpRequest.java           {username, email, firstName, lastName, password, confirmPassword}
    UserResponse.java            {id, username, email, roles, ...}

  entity/
    Role.java                    JPA entity (roles table)
    User.java                    JPA entity (users table, ManyToMany → roles)

  exception/
    BadRequestException.java     400 errors
    GlobalExceptionHandler.java  @RestControllerAdvice
    ResourceNotFoundException.java 404 errors

  filter/
    SecurityHeadersFilter.java   CSP, HSTS, X-Frame-Options, etc.
    SessionValidationFilter.java Session existence + auth validation

  repository/
    RoleRepository.java          JPA repository for Role
    UserRepository.java          JPA repository for User

  security/
    AuthorizationInterceptor.java    MVC interceptor for role-based path auth
    CustomUserDetailsService.java    Loads UserDetails from DB
    RolePermissionMapping.java       Path → allowed-roles mapping

  service/
    AuthService.java             Business logic: register, login, getUserById

  util/
    SecurityUtil.java            Client IP detection
    SecurityUtils.java           Static helpers: getCurrentUser(), hasRole()

  /auth/register          Public       Public        No auth required
  /auth/logout            Public       Public        No auth required
  /health                 Public       Public        No auth required
  /dashboard/**           Allowed      Allowed       Any authenticated user
  /admin/**               Denied       Allowed       Admin only
  /activity/admin/**      Denied       Allowed       Admin only
